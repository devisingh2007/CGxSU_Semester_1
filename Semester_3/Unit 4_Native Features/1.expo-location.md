# Location (`expo-location`)

## What is `expo-location`?

`expo-location` is an Expo SDK module that allows your React Native application to access the device's location using GPS, Wi-Fi, and mobile networks.

With this package, you can:

- Get the user's current location
- Track the user's location in real time
- Get the last known location
- Convert latitude and longitude into a readable address
- Convert an address into latitude and longitude
- Check whether location services are enabled
- Get the device's heading (compass direction)
- Request location permissions from the user

`expo-location` is commonly used in applications like:

- Food Delivery Apps
- Ride Booking Apps
- Maps & Navigation Apps
- Fitness Tracking Apps
- Weather Apps
- Nearby Places Finder
- Attendance Apps
- Travel Applications

---

# Why Do We Need Location?

Many modern mobile applications depend on the user's location to provide better services.

Examples:

### Food Delivery

- Show nearby restaurants
- Track delivery partner
- Detect delivery address

### Ride Booking

- Detect pickup location
- Track driver in real time
- Calculate travel distance

### Weather App

- Detect current city
- Show local weather

### Fitness App

- Track running route
- Calculate total distance
- Measure speed

### Navigation App

- Show current position
- Find shortest path
- Provide turn-by-turn directions

# How Does Expo Get Your Location?

Your device can determine its location using multiple sources.

## 1. GPS (Global Positioning System)

GPS uses satellites to calculate your exact position.

Advantages:

- Very accurate
- Works outdoors
- Best for navigation

Disadvantages:

- Uses more battery
- Can be slower indoors

---

## 2. Wi-Fi

Nearby Wi-Fi networks can help estimate your location.

Advantages:

- Fast
- Works indoors

Disadvantages:

- Less accurate than GPS

---

## 3. Mobile Network (Cell Towers)

The device estimates location using nearby cellular towers.

Advantages:

- Available almost everywhere
- Low battery usage

Disadvantages:

- Less accurate

---

Expo automatically chooses the best available source depending on your requested accuracy.

---

# What is GPS?

GPS (Global Positioning System) is a satellite-based navigation system.

There are multiple satellites orbiting around the Earth.

Your phone communicates with these satellites to determine its exact location.

The location is represented using:

- Latitude
- Longitude

Example:

```text
Latitude : 28.6139
Longitude: 77.2090
```

This location represents New Delhi.

---

# What is Latitude?

Latitude tells how far a location is north or south of the Equator.

Range:

```text
-90° to +90°
```

Examples:

```text
New Delhi

Latitude:
28.6139
```

```text
Mumbai

Latitude:
19.0760
```

Positive latitude means:

North of the Equator.

Negative latitude means:

South of the Equator.

---

# What is Longitude?

Longitude tells how far a location is east or west of the Prime Meridian.

Range:

```text
-180° to +180°
```

Examples:

```text
New Delhi

Longitude:
77.2090
```

```text
Mumbai

Longitude:
72.8777
```

Positive longitude means:

East of the Prime Meridian.

Negative longitude means:

West of the Prime Meridian.

---

# Together They Represent a Location

A location is identified using both values.

Example:

```text
Latitude : 28.6139

Longitude: 77.2090
```

Without both values, the location cannot be accurately identified.

---

# What is Accuracy?

Accuracy tells how close the reported location is to the user's actual position.

Example:

```text
Accuracy:
5 meters
```

This means the user is somewhere within approximately 5 meters of the reported coordinates.

Lower accuracy value = More precise location.

Example:

```text
Accuracy = 3 meters
```

Very accurate.

```text
Accuracy = 100 meters
```

Less accurate.

---

# Foreground Location

Foreground location means your application accesses the user's location only while the app is open and actively being used.

Examples:

- Maps App
- Food Delivery App
- Ride Booking App

This is the most common type of location permission.

---

# Background Location

Background location means the application can continue receiving location updates even after the user minimizes or closes the app.

Examples:

- Fitness Tracker
- Running App
- Delivery Partner Tracking
- Fleet Tracking

Background location requires additional permissions and should only be used when necessary.

# Chapter 2 - Installation & Setup

Before we can access the device's location, we need to install the **expo-location** package and configure the required permissions.

---

# Step 1 - Install Expo Location

Install the official Expo Location package.

```bash
npx expo install expo-location
```

Why do we use `expo install` instead of `npm install`?

Because Expo installs the version that is compatible with your current Expo SDK.

Example:

```bash
npx expo install expo-location
```

instead of

```bash
npm install expo-location
```

This avoids version compatibility issues.

---

# Step 2 - Import the Package

Now import Location inside your component.

```js
import * as Location from "expo-location";
```

Why `* as Location`?

Because the package exports many functions like:

- requestForegroundPermissionsAsync()
- getCurrentPositionAsync()
- watchPositionAsync()
- reverseGeocodeAsync()
- geocodeAsync()
- getHeadingAsync()

Instead of importing them one by one, we import everything as **Location**.

---

# Installation Complete

Now the package is ready to use.

Next we need permission from the user.

Without permission, the app **cannot access the device location**.

# Understanding Location Permissions

For privacy reasons, Android and iOS never allow an app to access location directly.

The app must first ask the user for permission.

Example:

```
Allow "My App" to access your location?

Allow While Using App

Don't Allow
```

If the user taps **Allow**, the app can access location.

If the user taps **Don't Allow**, the app cannot access location.

---

# Types of Location Permissions

Expo provides two types of permissions.

## 1. Foreground Permission

The app can access location only while it is open.

Example:

- Google Maps
- Uber
- Swiggy
- Zomato

Function:

```js
Location.requestForegroundPermissionsAsync()
```

This is the permission we'll use in most apps.

---

## 2. Background Permission

The app can continue receiving location updates even after it goes into the background.

Examples:

- Fitness Apps
- Delivery Partner Apps
- Running Tracker
- Live GPS Tracking

Function:

```js
Location.requestBackgroundPermissionsAsync()
```

We'll learn this later in the advanced section.

---

# Chapter 3 - Request Foreground Location Permission

Before accessing the user's location, we must first request permission.

Without permission, Expo cannot access the device's GPS.

# What is Foreground Permission?

Foreground permission allows your app to access the user's location **only while the app is open and being used**.

For example:

- Google Maps
- Swiggy
- Zomato
- Uber

When the app goes into the background, it cannot continue tracking the location (unless Background Permission is granted).

# Function Used

Expo provides the following function:

```js
Location.requestForegroundPermissionsAsync()

This function opens the system permission popup.

Example:

```

The function waits for the user's response and then returns a permission object.

# Chapter 4 - Get Current Location

Now that we have permission, we can access the user's current location.

Expo provides the following function:

```js
Location.getCurrentPositionAsync()
```

This function gets the device's current GPS location and returns a **Location Object**.

---

# What is Current Location?

Current Location means the **device's live location at this moment**.

For example:

Suppose you are standing at India Gate, New Delhi.

When you call:

```js
Location.getCurrentPositionAsync()
```

Expo communicates with the device's GPS (or Wi-Fi/Mobile Network if needed) and returns your current coordinates.

Example:

```text
Latitude : 28.6129
Longitude: 77.2295
```

---

# Syntax

```js
const location = await Location.getCurrentPositionAsync();
```

Since finding the location takes some time, this function returns a **Promise**.

That's why we use `await`.

User Opens App

        ↓

        ↓

        ↓

        ↓

# Chapter 5 - Last Known Location

In the previous chapter, we learned how to get the **Current Location** using GPS.

Now we'll learn about **Last Known Location**.

Expo provides the following function:

```js
Location.getLastKnownPositionAsync()
```

This function returns the **last location stored by the device**.

Unlike `getCurrentPositionAsync()`, it **does not immediately access GPS**.

---

# What is Last Known Location?

Last Known Location is the **most recently saved location** available on the device.

Think of it like a cache.

Example:

Suppose:

- You opened Google Maps 10 minutes ago.
- Your phone already saved your location.

Now your app calls:

```js
Location.getLastKnownPositionAsync()
```

Instead of turning on GPS again, Expo simply returns the cached location.

---

# Real Life Example

Imagine this situation.

```
10:00 AM

You open Google Maps.

↓

GPS finds your location.

↓

Phone saves the location.
```

After 15 minutes,

```
10:15 AM

You open your app.

↓

Instead of finding location again,

↓

Phone returns the saved location.
```

This is called **Last Known Location**.

---

# Why Use Last Known Location?

There are several advantages.

 Faster Response

No need to wait for GPS.

---

 Saves Battery

GPS consumes battery.

Using cached location reduces battery usage.

---

 Good User Experience

The app can immediately display a location while waiting for the latest GPS result.

Many apps first show the cached location and then update it with the current location.

---

# Function

```js
Location.getLastKnownPositionAsync()
```

---

# Can It Return `null`?

Yes.

If the device has **never determined a location before**, there may not be any cached location.

Example:

```js
const location =
  await Location.getLastKnownPositionAsync();

console.log(location);
```

Output:

```js
null
```

This usually happens when:

- GPS has never been used.
- Location history is unavailable.
- Device was recently reset.

Always check for `null`.

# Safe Example

```jsx
import { View, Button } from "react-native";
import * as Location from "expo-location";

export default function App() {
  const getLastLocation = async () => {
    try {
      // Permission
      const permission =
        await Location.requestForegroundPermissionsAsync();

      if (!permission.granted) {
        console.log("Permission Denied");
        return;
      }

      // Check last known location
      let lastLocation =
        await Location.getLastKnownPositionAsync();

      // If no cached location exists
      if (!lastLocation) {
        console.log("No Last Known Location Found");
        console.log("Fetching Current Location...");

        // Get current location
        const currentLocation =
          await Location.getCurrentPositionAsync({
            accuracy: Location.Accuracy.High,
          });

        console.log("Current Location:");
        console.log(currentLocation);

        // Now check again
        lastLocation =
          await Location.getLastKnownPositionAsync();
      }

      console.log("Last Known Location:");
      console.log(lastLocation);
    } catch (error) {
      console.log(error);
    }
  };

  return (
    <View
      style={{
        flex: 1,
        justifyContent: "center",
        alignItems: "center",
      }}
    >
      <Button
        title="Get Last Known Location"
        onPress={getLastLocation}
      />
    </View>
  );
}
```

      await Location.requestForegroundPermissionsAsync();

      await Location.getLastKnownPositionAsync();

        justifyContent:"center",
        alignItems:"center",
        gap:10
      }}
    >

        title="Get Last Known Location"
        onPress={getLocation}

        <>
          <Text>
            Latitude: {location.coords.latitude}
          </Text>

          <Text>
            Longitude: {location.coords.longitude}
          </Text>

          <Text>
            Accuracy: {location.coords.accuracy}
          </Text>
        </>
      ) : (
        <Text>No Cached Location Available</Text>
      )}

    </View>

  );

}

# Chapter 6 - Live Location Tracking (`watchPositionAsync()`)

In the previous chapters, we learned how to get:

- Current Location
- Last Known Location

Both of these return the location **only once**.

But what if we want to continuously track the user's location?

For that, Expo provides:

```js
Location.watchPositionAsync()
```

This function keeps listening for location updates and automatically notifies your app whenever the user's location changes.

---

# What is Live Location Tracking?

Live Location Tracking means continuously receiving the user's location while they move.

For example:

```
You start walking.

↓

Your location changes.

↓

App receives new coordinates.

↓

You walk again.

↓

App receives updated coordinates.

↓

This continues until tracking is stopped.
```

Unlike `getCurrentPositionAsync()`, you don't have to call the function repeatedly.

---

- Google Maps Navigation
- Uber
- Ola
- Rapido
- Swiggy Delivery
- Zomato Delivery
- Running Tracker
- Cycling Apps

# Update Frequency

By default, updates happen whenever the device detects a meaningful location change.

You can control this using options.

### Update Every 10 Meters

```js
await Location.watchPositionAsync(
  {
    accuracy: Location.Accuracy.High,
    distanceInterval: 10,
  },
  (location) => {
    console.log(location);
  }
);
```

This means a new update is received only after moving approximately **10 meters**.

---

### Update Every 5 Seconds

```js
await Location.watchPositionAsync(
  {
    accuracy: Location.Accuracy.High,
    timeInterval: 5000,
  },
  (location) => {
    console.log(location);
  }
);
```

> **Note:** `timeInterval` is mainly supported on Android. On iOS, update timing is determined by the operating system.

---

# Common Options

## accuracy

Controls GPS accuracy.

```js
accuracy: Location.Accuracy.High
```

---

## distanceInterval

Minimum distance (in meters) before sending another update.

```js
distanceInterval: 5
```

---

## timeInterval

Minimum time (in milliseconds) between updates.

```js
timeInterval: 3000
```

---

# Stopping Live Tracking

This is **very important**.

`watchPositionAsync()` returns a **subscription object**.

```js
const subscription =
  await Location.watchPositionAsync(...);
```

To stop tracking:

```js
subscription.remove();
```

If you don't remove the subscription:

- GPS keeps running
- Battery drains faster
- Memory usage increases

---

# Complete Example (Start & Stop Tracking)

```jsx
import { useRef, useState } from "react";
import { View, Button, Text } from "react-native";
import * as Location from "expo-location";

export default function App() {
  const [location, setLocation] = useState(null);

  const subscriptionRef = useRef(null);

  const startTracking = async () => {
    const permission =
      await Location.requestForegroundPermissionsAsync();

    if (!permission.granted) return;

    subscriptionRef.current =
      await Location.watchPositionAsync(
        {
          accuracy: Location.Accuracy.High,
          distanceInterval: 5,
        },
        (location) => {
          setLocation(location);
        }
      );
  };

  const stopTracking = () => {
    if (subscriptionRef.current) {
      subscriptionRef.current.remove();
      subscriptionRef.current = null;
      console.log("Tracking Stopped");
    }
  };

  return (
    <View
      style={{
        flex: 1,
        justifyContent: "center",
        alignItems: "center",
        gap: 10,
      }}
    >
      <Button
        title="Start Tracking"
        onPress={startTracking}
      />

      <Button
        title="Stop Tracking"
        onPress={stopTracking}
      />

      {location && (
        <>
          <Text>
            Latitude: {location.coords.latitude}
          </Text>

          <Text>
            Longitude: {location.coords.longitude}
          </Text>
        </>
      )}
    </View>
  );
}
```

|------------------|---------------|
| Returns one location | Returns continuous updates |
| Uses `getCurrentPositionAsync()` | Uses `watchPositionAsync()` |
| Manual refresh required | Automatic updates |
| Lower battery usage | Higher battery usage |
| Good for one-time checks | Good for navigation and tracking |

# What is Location Accuracy?

Location accuracy determines **how precisely Expo should determine the device's location**.

Higher accuracy:

- Uses GPS more frequently
- Consumes more battery
- Takes more time
- Gives more precise coordinates

Lower accuracy:

- Uses Wi-Fi / Cell Towers
- Saves battery
- Faster response
- Less precise

Medium
```

---

### Option 3

```
Your friend is standing at Gate No. 3 of India Gate.
```

Accuracy:

```
Very High
```

The more accurate the location, the more resources the phone uses.

Location.Accuracy.Low

```

Let's understand each one.

---

# 1. Lowest

```js
Location.Accuracy.Lowest
```

- Nearby Networks

# 2. Low

```js

```

Slightly better than Lowest.

Uses:

- Wi-Fi
- Mobile Networks

Characteristics:

- Low Battery Usage
- Fast Response
- Acceptable Accuracy

Best For:

- Store Finder
- Restaurant Finder
- Basic Location Apps

---

# 3. Balanced

```js
Location.Accuracy.Balanced
```

This is a balance between:

- Battery
- Speed
- Accuracy

Expo may combine:

- GPS
- Wi-Fi
- Mobile Network

Characteristics:

- Medium Battery Usage
- Good Accuracy
- Good Performance

Best For:

- Most Mobile Apps
- Delivery Apps
- Social Apps
- Attendance Apps

This is the recommended default for many applications.

---

# 4. High

```js
Location.Accuracy.High
```

Uses GPS more aggressively.

Characteristics:

- High Accuracy
- Higher Battery Usage
- Slightly Slower

Best For:

- Ride Booking
- Navigation
- Live Tracking

Example:

```js

  await Location.getCurrentPositionAsync({
    accuracy: Location.Accuracy.High,
  });
```

---

# 5. Highest

```js
Location.Accuracy.Highest
```

Provides even more accurate results.

Characteristics:

- Very High Accuracy
- High Battery Consumption
- Slower Response

Best For:

- Survey Apps
- Field Work
- Precision Tracking

---

# 6. Best For Navigation

```js
Location.Accuracy.BestForNavigation
```

This is the highest accuracy available.

It continuously tries to provide the most accurate GPS location.

Characteristics:

- Maximum Accuracy
- Maximum Battery Usage
- Best for continuous movement

Best For:

- Google Maps
- Uber
- Ola
- Running Apps
- Cycling Apps

Avoid using it unless your app truly requires navigation-level accuracy.

# Chapter 10 - Device Heading (Compass)

So far, we've learned how to get the user's location.

---

# What is Heading?

Heading tells us **the direction in which the device is pointing**.

For example:

If you're holding your phone toward the north, the heading will be close to:

```
0°
```

If you turn toward the east:

```
90°
```

Turn toward the south:

```
180°
```

Turn toward the west:

```
270°
```

---

# Real-Life Example

Suppose you open Google Maps.

You are standing at one place.

Even though your location doesn't change,

the blue arrow keeps rotating.

Why?

Because the app is reading the **device heading**.

Example:

```
Current Location

↓

Latitude
Longitude

↓

Device Rotates

↓

Heading Changes
```

Notice:

Location remains the same.

Only the direction changes.

# Important Notes

### 1. Heading Requires a Compass Sensor

Not every phone has a magnetometer.

If the device doesn't support it, heading values may not be available or may be inaccurate.

---

### 2. Test on a Real Device

The Android Emulator and iOS Simulator usually **cannot provide real compass data**.

Always test heading on a physical phone.

---

### 3. Calibration

Sometimes the compass needs calibration.

The operating system may ask the user to move the phone in a **figure-eight (∞)** pattern.

This improves compass accuracy.

---

# Common Mistakes

## 1. Expecting Location to Change

Heading tells **direction**, not **location**.

Even if you're standing still, the heading changes when you rotate the phone.

---

## 2. Testing Only on Emulator

Most emulators don't have a compass sensor.

Always use a real device.

---

## 3. Confusing Heading with GPS

Heading uses the **magnetometer**.

Location uses **GPS/Wi-Fi/Cell Towers**.

They are different sensors.
