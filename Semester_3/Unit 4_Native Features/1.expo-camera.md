# Camera (`expo-camera`)

## What is `expo-camera`?

`expo-camera` is an Expo SDK module that allows your React Native application to access the device's built-in camera.

Using this package, you can:

* Open the live camera preview
* Take photos
* Record videos
* Scan QR codes
* Scan barcodes
* Control the flash while capturing photos
* Enable or disable the camera torch (flashlight)
* Switch between the front and back camera
* Zoom the camera programmatically
* Pinch to zoom using touch gestures
* Request and manage camera permissions
* Request microphone permissions (for video recording)

Instead of writing native Android (Java/Kotlin) or iOS (Swift/Objective-C) code, Expo provides a simple JavaScript API that works seamlessly on both platforms.

---

# Camera Permission

For privacy and security reasons, mobile applications cannot access the camera directly.

Whenever an app wants to use the camera, Android and iOS ask the user for permission.

### Example

```text
Allow MyApp to access the Camera?

[ Allow ]      [ Don't Allow ]
```

If the user denies permission, the application cannot open the camera.

---

## Permission Flow

```text
App Opens
     │
     ▼
Request Camera Permission
     │
     ▼
Permission Granted?
     │
 ┌───┴───┐
 │       │
Yes      No
 │       │
 ▼       ▼
Open     Show Permission
Camera   Screen
```

### Note

* **Camera Permission** is required for taking photos, recording videos, scanning QR codes, and scanning barcodes.
* **Microphone Permission** is required only when recording videos with audio.

# 2. `useCameraPermissions()`

## What is `useCameraPermissions()`?

Before an application can use the device camera, it must ask the user for permission.

The `useCameraPermissions()` hook helps us:

* Check the current camera permission status.
* Request camera permission from the user.
* Know whether permission has been granted or denied.

Without camera permission, the application cannot access or display the device camera.

---

## Basic Example

```jsx
import { useCameraPermissions } from "expo-camera";

export default function App() {
  const [permission, requestPermission] =
    useCameraPermissions();
}
```

---

## What Does It Return?

```jsx
const [permission, requestPermission] =
  useCameraPermissions();
```

This hook returns two values:

| Value                 | Description                                   |
| --------------------- | --------------------------------------------- |
| `permission`          | Contains the current camera permission status |
| `requestPermission()` | Requests camera permission from the user      |

---

## Permission States

There are three possible permission states.

### 1. Granted

The user has allowed camera access.

```jsx
permission.granted === true
```

Result

```text
Camera Opens
```

---

### 2. Denied

The user has rejected camera access.

```jsx
permission.granted === false
```

Result

```text
Cannot Open Camera
```

---

### 3. Undetermined

The application has never requested camera permission before.

```text
First Time Opening App
        │
        ▼
Permission Not Decided Yet
```

In this case, the application should request permission.

```jsx
requestPermission();
```

---

## Checking Permission

```jsx
if (!permission?.granted) {
  return <Text>Camera Permission Required</Text>;
}
```

### Explanation

If permission has not been granted, we display a message instead of opening the camera.

---

## Requesting Permission

```jsx
<Button
  title="Allow Camera"
  onPress={requestPermission}
/>
```

### Permission Flow

```text
User Presses Button
        │
        ▼
requestPermission()
        │
        ▼
Permission Dialog Opens
        │
        ▼
Allow / Don't Allow
```

---

## Complete Example

```jsx
import { Text } from "react-native";
import {
  CameraView,
  useCameraPermissions,
} from "expo-camera";

export default function App() {
  const [permission] = useCameraPermissions();

  if (!permission?.granted) {
    return <Text>Permission Required</Text>;
  }

  return (
    <CameraView
      style={{ flex: 1 }}
      facing="back"
    />
  );
}
```

# 1. `facing`

## What is `facing`?

The `facing` prop determines **which camera** should be opened in the application.

Most smartphones have at least two cameras:

* **Back Camera (Rear Camera)**
* **Front Camera (Selfie Camera)**

By changing the value of the `facing` prop, we can choose which camera the user should see when the application starts.

---

## Possible Values

The `facing` prop accepts two values.

| Value     | Description                     |
| --------- | ------------------------------- |
| `"back"`  | Opens the rear camera           |
| `"front"` | Opens the front (selfie) camera |

---

## `facing="back"`

The back camera is generally used for capturing objects, documents, landscapes, and high-quality photos.

### Example

```jsx
<CameraView
  style={{ flex: 1 }}
  facing="back"
/>
```

### Explanation

```jsx
facing="back"
```

* Opens the rear camera.
* Usually provides better image quality than the front camera.
* Best for photographing objects, documents, and scenery.

### Output

```text
Rear Camera Opens
```

---

## `facing="front"`

The front camera is mainly used for selfies and video calls.

### Example

```jsx
<CameraView
  style={{ flex: 1 }}
  facing="front"
/>
```

### Explanation

```jsx
facing="front"
```

* Opens the front (selfie) camera.
* Useful when the user wants to capture themselves.
* Commonly used for video calls and face verification.

### Output

```text
Front Camera Opens
```

# Changing the Camera Dynamically

Instead of keeping the camera fixed, we can change it while the application is running.

This is done using **React State**.

### Example

```jsx
const [facing, setFacing] = useState("back");

<CameraView
  style={{ flex: 1 }}
  facing={facing}
/>
```

### Explanation

```jsx
const [facing, setFacing] = useState("back");
```

* Creates a state variable named `facing`.
* Initially, the back camera is selected.

```jsx
facing={facing}
```

* The `CameraView` always uses the current value stored in the `facing` state.
* Whenever the state changes, the camera updates automatically.

---

## Switching to the Front Camera

```jsx
setFacing("front");
```

### Result

```text
Back Camera
      │
      ▼
Front Camera
```

---

## Switching Back to the Rear Camera

```jsx
setFacing("back");
```

### Result

```text
Front Camera
      │
      ▼
Back Camera
```

# 2. `flash`

## What is `flash`?

The `flash` prop controls the **camera flash** while taking photos.

The flash helps capture brighter and clearer images in **low-light** or **dark environments**.

Think of it like the **Flash** button in your phone's default Camera application.

---

## Flash Modes

The `flash` prop supports three modes.

| Value    | Description                                          |
| -------- | ---------------------------------------------------- |
| `"off"`  | Flash is always disabled                             |
| `"on"`   | Flash is always enabled                              |
| `"auto"` | Camera automatically decides whether flash is needed |

---

## `flash="off"`

When the flash mode is set to **`"off"`**, the flash never turns on.

### Example

```jsx
<CameraView
  style={{ flex: 1 }}
  flash="off"
/>
```

### Explanation

```jsx
flash="off"
```

* Flash remains disabled.
* Saves battery.
* Best for daylight or well-lit environments.

### Output

```text
Flash Disabled
```

---

## `flash="on"`

When the flash mode is set to **`"on"`**, the flash turns on every time a photo is captured.

### Example

```jsx
<CameraView
  style={{ flex: 1 }}
  flash="on"
/>
```

### Explanation

```jsx
flash="on"
```

* Flash always turns on.
* Useful in dark rooms or at night.
* Produces brighter photos.

### Output

```text
Flash Enabled
```

---

## `flash="auto"`

When the flash mode is set to **`"auto"`**, the camera decides whether the flash should be used.

If the environment is dark, the flash turns on automatically.

If there is enough light, the flash remains off.

### Example

```jsx
<CameraView
  style={{ flex: 1 }}
  flash="auto"
/>
```

### Explanation

```jsx
flash="auto"
```

* Camera detects the surrounding light.
* Automatically decides whether to use the flash.
* Provides a good balance between brightness and battery usage.

### Output

```text
Dark Environment
        │
        ▼
Flash Turns On

Bright Environment
        │
        ▼
Flash Stays Off
```

# 3. `autofocus`

## What is `autofocus`?

The `autofocus` prop controls whether the camera should **automatically focus on the subject** before capturing a photo or recording a video.

Instead of taking blurry pictures, the camera continuously adjusts its focus to keep the subject sharp and clear.

Think of it like your phone's Camera app automatically focusing when you point it at a person's face, a document, or an object.

---

## Autofocus Modes

The `autofocus` prop supports two modes.

| Value   | Description                                             |
| ------- | ------------------------------------------------------- |
| `"on"`  | Automatically focuses on the subject                    |
| `"off"` | Keeps the current focus without adjusting automatically |

```text
      ▼
Sharp Image
```

# 4. `mirror`

## What is `mirror`?

The `mirror` prop controls whether the camera preview or captured image is displayed in its **original orientation** or **flipped horizontally**.

It is mainly useful when using the **front (selfie) camera**.

---

## Mirror Values

The `mirror` prop accepts two boolean values.

| Value   | Description                                         |
| ------- | --------------------------------------------------- |
| `true`  | Keeps the preview/image in its original orientation |
| `false` | Flips the preview/image horizontally                |

---

## `mirror={true}`

When `mirror` is **true**, the camera preview is displayed in its original orientation.

### Example

```jsx
<CameraView
  style={{ flex: 1 }}
  mirror={true}
/>
```

### Explanation

```jsx
mirror={true}
```

* Displays the preview without flipping it.
* Shows the image in its original orientation.
* Useful when you want to see the camera output as it is captured.

### Output

```text
Original Preview
```

---

## `mirror={false}`

When `mirror` is **false**, the camera preview is flipped horizontally.

### Example

```jsx
<CameraView
  style={{ flex: 1 }}
  mirror={false}
/>
```

### Explanation

```jsx
mirror={false}
```

* Flips the preview from left to right.
* Produces a mirrored image.
* Useful when a mirrored preview is preferred.

### Output

```text
Original Preview
      │
      ▼
Mirrored Preview
```

---

# Why Do We Need `mirror`?

The `mirror` prop is mainly useful when using the **front camera**.

For example, while taking a selfie:

Without mirroring:

```text
You Raise Right Hand
        │
        ▼
Preview Shows Left Side
```

With mirroring:

```text
You Raise Right Hand
        │
        ▼
Preview Also Shows Right Hand
```

A mirrored preview often feels more natural because it behaves like looking into a mirror.

# 5. `mute`

## What is `mute`?

The `mute` prop controls whether the **microphone records audio while recording a video**.

It only affects **video recording** and has **no effect when taking photos**.

Think of it like the **Microphone On/Off** option in your phone's Camera application.

---

## Mute Values

The `mute` prop accepts two boolean values.

| Value   | Description                 |

# `takePictureAsync()`

## What is `takePictureAsync()`?

`takePictureAsync()` is a method provided by `expo-camera` that is used to **capture a photo** from the device camera.

When the user taps the **Capture** button, this method takes a picture and returns information about the captured image.

Think of it like pressing the **shutter button** in your phone's Camera application.

Unlike camera props (such as `flash`, `zoom`, or `facing`), `takePictureAsync()` performs an **action**. It tells the camera to capture a photo at that moment.

---

## Is `takePictureAsync()` Asynchronous?

Yes.

`takePictureAsync()` is an **asynchronous method**, which means it does not return the captured photo immediately.

Instead, it returns a **Promise**.

Once the camera finishes capturing and processing the image, the Promise resolves with an object containing information about the captured photo.

Because of this, we normally use `await` with `takePictureAsync()`.

---

# What Does It Return?

After capturing a photo, `takePictureAsync()` returns an object containing information about the image.

Some common properties are:

```text

Width

Height
```

### Example Output

```json
  "width": 3024,
  "height": 4032
}
```

This information is called **metadata**, which means **data about the image**, not the image itself.

# `recordAsync()`

## What is `recordAsync()`?

`recordAsync()` is a method provided by `expo-camera` that is used to **start recording a video**.

When the user taps the **Record** button, this method begins recording video using the device camera.

Unlike `takePictureAsync()`, which captures a single image, `recordAsync()` continuously records video until it is stopped.

Think of it like pressing the **Record** button in your phone's Camera application.

---

## Is `recordAsync()` Asynchronous?

Yes.

`recordAsync()` is an **asynchronous method**, which means it returns a **Promise**.

The Promise resolves **only after the recording has finished**.

Because of this, we usually call it using `await`.

---

# What Does It Return?

After recording stops, `recordAsync()` returns an object containing information about the recorded video.

The most common property is:



The returned `uri` represents the location of the recorded video file.

# Preventing Duplicate Scans

## Why Do Duplicate Scans Happen?

`onBarcodeScanned` is called **every time** the camera detects a supported QR code or barcode.

Since the camera continuously analyzes the live preview, keeping the same QR code in front of the camera causes the callback to execute repeatedly.

For example, if the camera detects the same QR code for 3 seconds, the callback may run many times during those 3 seconds.

---

```text
↓

↓

https://expo.dev

↓

onBarcodeScanned()

↓

https://expo.dev

↓

Repeated Again and Again...
```

This may result in:

* Multiple alerts
* Multiple API requests
* Duplicate database entries
* Poor user experience

---

# The Solution

A common solution is to temporarily **disable scanning** after the first successful scan.

This can be done using React State.

```jsx
  }
/>
```

---

# Why Do We Pass `undefined`?

Expo Camera expects a callback function.

If we pass:

```jsx
handleBarcodeScanned
```

Scanning continues.

If we pass:

```jsx
undefined
```

There is no callback available.

Since no callback exists,

Expo Camera stops notifying the application about newly detected codes.

# Resetting the Scanner

## Why Do We Need to Reset the Scanner?

After a successful scan, we usually disable scanning to prevent duplicate scans.

```jsx id="0bkq7d"
setScanned(true);
```

This prevents `onBarcodeScanned` from being called again.

However, what if the user wants to scan **another QR code or barcode**?

To allow another scan, we need to enable scanning again.

This is called **resetting the scanner**.

---

# The Solution

To enable scanning again, simply change the `scanned` state back to `false`.

```jsx id="v10ij8"
setScanned(false);
```

Once `scanned` becomes `false`, the camera starts listening for QR codes and barcodes again.

---

# How It Works

Initially:

```text id="48fv0v"
scanned = true

↓

Scanning Disabled
```

After resetting:

```jsx id="ms7w25"
setScanned(false);
```

Result:

```text id="qxfzha"
scanned = false

↓

Scanning Enabled
```

## Complete Code

```jsx
import { useState } from "react";
import { View, Text, Button, StyleSheet } from "react-native";
import {
  CameraView,
  useCameraPermissions,
} from "expo-camera";

export default function QRScanner() {
  const [permission, requestPermission] =
    useCameraPermissions();

  const [scanned, setScanned] = useState(false);

  const [result, setResult] = useState(null);

  if (!permission) {
    return <View />;
  }

  if (!permission.granted) {
    return (
      <View style={styles.center}>
        <Text>
          Camera permission is required.
        </Text>

        <Button
          title="Grant Permission"
          onPress={requestPermission}
        />
      </View>
    );
  }

  const handleBarcodeScanned = ({ type, data }) => {
    setScanned(true);

    setResult({
      type,
      data,
    });
  };

  return (
    <View style={{ flex: 1 }}>
      <CameraView
        style={{ flex: 1 }}
        onBarcodeScanned={
          scanned
            ? undefined
            : handleBarcodeScanned
        }
      />

      {result && (
        <View style={styles.resultContainer}>
          <Text>
            Type: {result.type}
          </Text>

          <Text>
            Data: {result.data}
          </Text>
        </View>
      )}

      {scanned && (
        <Button
          title="Scan Again"
          onPress={() => {
            setResult(null);
            setScanned(false);
          }}
        />
      )}
    </View>
  );
}

const styles = StyleSheet.create({
  center: {
    flex: 1,
    justifyContent: "center",
    alignItems: "center",
  },

  resultContainer: {
    padding: 20,
    backgroundColor: "#fff",
  },
});
```

# `barcodeScannerSettings`

## What is `barcodeScannerSettings`?

The `barcodeScannerSettings` prop allows you to control **which types of QR codes or barcodes** the camera should scan.

By default, Expo Camera tries to detect **all supported barcode formats**.

If your application only needs QR codes (or only specific barcode types), you can limit the scanner using `barcodeScannerSettings`.

This improves scanning accuracy and avoids detecting unnecessary barcode types.

---

# Why Do We Need `barcodeScannerSettings`?

Imagine you're building a **Payment App**.

The application should only scan **QR codes**.

If the camera also scans product barcodes, the user may accidentally scan the wrong code.

Instead, we can tell Expo Camera to scan only QR codes.

---

# Syntax

```jsx
<CameraView
  barcodeScannerSettings={{
    barcodeTypes: ["qr"],
  }}
/>
```

---

# `barcodeTypes`

The `barcodeTypes` property accepts an array of barcode formats that should be detected.

### Example

```jsx
barcodeScannerSettings={{
  barcodeTypes: ["qr"],
}}
```

This tells Expo Camera:

> "Only scan QR codes."

---
